# Plan: Interview Training Fixes (5 issues)

## Summary
Fix five regressions in the live AI interview module so it actually behaves like a Korean university mock-interview: native Korean accent, AI starts the conversation, the session ends itself with a proper goodbye, every session is recorded and replayable from history, and a structured AI feedback report is produced after every session.

## User Story
As a Korean university applicant practising in the Hanguk app,
I want the interview module to feel like a real interview — native Korean professor voice, the interviewer initiates and closes the conversation, I can replay my past sessions, and I get a written feedback report at the end —
so that practice sessions are actually useful preparation rather than a broken voice toy.

## Problem → Solution
**Current state.** The five features are *wired in code* but broken at runtime:
- Korean voice IDs in `InterviewPersonaConfig.getVoiceId()` are non-Korean ElevenLabs voices forced through `eleven_multilingual_v2` — they speak Korean *with* an English accent.
- Vapi `firstMessage` is set but `firstMessageMode` is missing, so Vapi waits for user voice activity before the AI speaks.
- `[END_SESSION]` detection relies on a brittle string match in the assistant transcript and bypasses `endSession()`, so the DB row never flips to `completed` and feedback is never generated by the auto-end path.
- `vapi_call_id` is captured into Riverpod state but never persisted to `interview_sessions`, so opening an old session from history loads either the wrong recording or none.
- Post-session feedback only fires from the manual "End Session" button; the auto-end path skips it entirely.

**Desired state.** Native Korean voices play through Vapi, AI speaks first via `firstMessageMode: 'assistant-speaks-first'`, auto-end is triggered by Vapi's `endCall` tool-call event (not a transcript string), every session writes `vapi_call_id` to the DB, and both auto-end and manual-end paths converge on a single `endSession() → feedback` flow.

## Patterns to Mirror

### VAPI EVENT LISTENER (already correct in this repo)
```dart
// SOURCE: interview_active_view.dart:123-187
_eventSub = _call?.onEvent.listen((event) {
  if (!mounted) return;
  final eventLabel = event.label;
  final eventValue = event.value;
  // ...
});
```
Pattern: branch on `eventLabel` first (`'message'`, `'call-end'`, `'status-update'`), then for `'message'` events branch on `eventValue['type']` (`'speech-start'`, `'speech-end'`, `'transcript'`, `'tool-calls'`, `'function-call'`). Keep all branches in one switch-like chain — do NOT scatter event handling across multiple `.listen()` callbacks.

### SINGLE TEARDOWN POINT (already correct)
```dart
// SOURCE: interview_active_view.dart:204-223
void _stopCall() {
  if (_isStopping) return;
  _isStopping = true;
  // ...
}
```
Pattern: every code path that ends the call funnels through `_stopCall()` — never call `_call?.dispose()` directly. New auto-end logic must respect this.

### Task 3 — Sessions end automatically with a clear announcement
**ACTION**: Replace the `[END_SESSION]` string-match auto-end with a Vapi `tool-calls` event listener for the built-in `endCall` function. Keep `endCallFunctionEnabled: true`. Let the AI finish its closing speech before tearing down.

**IMPLEMENT**:
- In [`interview_active_view.dart:74-81`](../../../lib/features/training/presentation/widgets/interview_active_view.dart#L74), update the system-prompt closing instruction from `say EXACTLY the phrase "[END_SESSION]"` to `say a brief closing remark thanking the candidate, then call the endCall function`.
- In the Vapi event listener around [`interview_active_view.dart:148-187`](../../../lib/features/training/presentation/widgets/interview_active_view.dart#L148), add a branch for `eventValue['type'] == 'tool-calls'` (or `'function-call'` depending on Vapi version — log both and pick the one Vapi actually emits). When the tool name is `'endCall'`:
  1. Set `_aiRequestedEnd = true`.
  2. Wait for the next `'speech-end'` event so the goodbye is heard.
  3. Then call `_stopCall()` and `await ref.read(interviewProvider.notifier).endSession(...)`.
  4. Then `Navigator.pushReplacement` to `InterviewFeedbackView` (state.status will already be `'completed'` post-`endSession()`).
- Remove the `transcriptText.contains('[END_SESSION]')` branch entirely.
- Add a guard `_didEndSession` bool to prevent double-fire if user also taps the manual end button mid-flow.

**GOTCHA**: If Vapi emits the tool-call event *before* the AI has spoken the closing line, jumping to `_stopCall()` immediately will cut off audio mid-sentence. The `_aiRequestedEnd` → wait-for-speech-end → teardown sequence is non-negotiable. If `'speech-end'` doesn't arrive within 8 seconds (network glitch), force-teardown via timeout to avoid hanging.

**VALIDATE**:
- Run a full 4-phase interview to completion. AI must speak a closing remark, then call ends naturally, then user lands on feedback view.
- Manual end button still works mid-session and routes through the same `endSession()` → feedback view path.
- No double-feedback (verify only one row in `interview_sessions` flips to `status='completed'` per session).
