# i18n setup runbook

> When you're ready to localise the Flutter UI strings (English first,
> Uzbek second per ADR-004 amend 1, Vietnamese + Mongolian later),
> follow this. Estimated time: 4–6 hours for the initial pass across
> the uni_db screens.
>
> Do NOT do this mid-feature-work — i18n touches every screen and
> belongs in its own dedicated branch.

## 1. Dependencies

Add to `pubspec.yaml`:

```yaml
dependencies:
  flutter_localizations:
    sdk: flutter
  intl: ^0.19.0          # exact version aligned with flutter sdk

dev_dependencies:
  intl_utils: ^2.8.7

flutter:
  generate: true         # enables ARB → Dart codegen on pub get
```

Then:

```bash
flutter pub get
```

## 2. ARB scaffold

Create `lib/l10n/l10n.yaml`:

```yaml
arb-dir: lib/l10n
template-arb-file: intl_en.arb
output-localization-file: app_localizations.dart
output-class: AppLocalizations
preferred-supported-locales: ['en', 'uz']
```

Create `lib/l10n/intl_en.arb`:

## 3. Wire into MaterialApp

In `lib/main.dart`, update `HangukApp.build`:

```dart
import 'package:flutter_localizations/flutter_localizations.dart';
import 'l10n/app_localizations.dart';   // generated by intl_utils

return MaterialApp.router(
  ...
  localizationsDelegates: const [
    AppLocalizations.delegate,
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
    GlobalCupertinoLocalizations.delegate,
  ],
  supportedLocales: const [Locale('en'), Locale('uz')],
  // device_preview already provides Locale via DevicePreview.locale(context)
  locale: DevicePreview.locale(context),
);
```

## 4. Refactor strings on uni_db screens

Replace literal strings:

```dart
// Before
title: const Text('Track this institution'),

// After
title: Text(AppLocalizations.of(context)!.trackInstitution),
```

Pass through every `Text(...)` and `Tooltip(...)` in:

- `lib/features/uni_db/presentation/institution_detail_screen.dart`
- `lib/features/uni_db/presentation/institution_compare_screen.dart`
- `lib/features/uni_db/presentation/application_tracker_screen.dart`
- `lib/features/uni_db/presentation/notification_settings_screen.dart`
- `lib/features/uni_db/presentation/admin_review_screen.dart`
- `lib/features/uni_db/presentation/widgets/coming_soon_card.dart`

## 5. Wire the user's preferred language

The `profiles.preferred_language` column already carries `'uz'` for
Uzbek-speaking students by default. Bridge that into the MaterialApp
locale by:

1. Creating a Riverpod `userLocaleProvider` that reads
   `profiles.preferred_language` for the current `auth.uid()`
2. Passing the result to `MaterialApp.router`'s `locale` parameter
3. Falling back to `Locale('en')` when the user is signed-out or has
   no preference set

## 6. Push payload language

The `notify-tracked-changes` Edge Function already reads
`user_push_tokens.preferred_lang` per token (per Phase 3 design)
and selects the right title/body string from its in-function map.
That map only currently has en/ko/uz; add `vi` and `mn` keys for
those locales when you add Vietnamese and Mongolian.

## 7. Translation worker for ARB strings (optional)

If the team gets large enough that hand-translating ARBs becomes a
bottleneck, point the existing translation worker
(`services/uni_db/src/uni_db/workers/translate_worker.py`) at the
ARB JSON. The worker's glossary preserves brand terms (Hanguk, KAIST,
TOPIK) without retranslation. Output goes back as a candidate ARB the
in-office reviewer accepts/edits.

This isn't worth setting up until the ARB has 50+ strings.

## 8. CI gate

Add to the existing CI workflow:

```yaml
- name: Verify ARB completeness
  run: |
    diff <(jq -r 'keys[]' lib/l10n/intl_en.arb | grep -v '^@' | sort) \
         <(jq -r 'keys[]' lib/l10n/intl_uz.arb | grep -v '^@' | sort)
```

Fails the build if any string in `intl_en.arb` is missing from
`intl_uz.arb` (or vice versa), so partial translations don't ship.

## 9. Phase 4 expansion

Vietnamese (`vi`) and Mongolian (`mn`) ARBs follow the same pattern.
At that point you'd:

1. Add `intl_vi.arb` + `intl_mn.arb` next to the others
2. Extend `supportedLocales` in `main.dart`
3. Update the `notify-tracked-changes` Edge Function's title/body map
4. Flip `UNI_DB_TRANSLATION_LANGUAGES=en,uz,vi,mn` on the worker host

Per the existing config.py default, vi+mn translation flips on the
moment the env var is set — no further code change needed in the
translation pipeline.
